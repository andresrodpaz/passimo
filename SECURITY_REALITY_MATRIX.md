# Passimo — security reality matrix

**Date:** 2026-09-13 · **Method:** source review, database inspection, and adversarial requests against a running instance.

Classification rule: a control is **REAL** only when it was demonstrated — by an executed request, a database query, or a test that fails without it. Anything resting on reading the code alone is **UNVERIFIED**, however convincing the code looks.

| Control | Reality | Evidence | Tested | Production ready |
|---|---|---|---|---|
| **Tenant isolation (API layer)** | **REAL** | Merchant B's session naming A's `businessId` → `403` on customers, analytics, campaigns, segments, locations, gift-cards, team, wallet settings, card-link. B naming A's customer id under B's own tenant → `404`. | Live, 12 endpoints | ✅ |
| **Tenant isolation (DB layer)** | **PARTIAL** | RLS deliberately removed (migration `000018`); isolation is application-layer. `passimo_ensure_account` / `passimo_rotate_card_token` re-check the pair in SQL. `db:verify` cross-tenant verdict = 0. | Live + db:verify | ✅ with caveat — no defence-in-depth if a query forgets its filter |
| **Cross-tenant detection (release gate)** | **REAL (fixed this audit)** | Verdict sum omitted gift cards: an injected cross-tenant gift card reported **PASS**. After adding it → **FAIL, violations=1**; removed → PASS. | Injected + reverted | ✅ |
| **Authentication** | **REAL** | Sessions are DB rows keyed by `sha256(secret)`, with `expires_at` and `revoked_at` checked on every resolve. Cookie is `httpOnly`, `sameSite=lax`, `secure` in production. Old cookie after logout → `401`. | Live | ✅ |
| **RBAC** | **REAL** | `defineRoute` checks permissions before the handler; roles defined in `lib/auth/rbac.ts`. Seat cap, owner-immutability and invite single-use all enforced server-side (`verify:functional`). | Functional suite | ✅ |
| **Platform admin** | **REAL** | `requirePlatformAdmin()` requires a session **and** a `platform_admins` row; impersonation is a separate cookie and writes an audit trail. | Source | ⚠️ UNVERIFIED adversarially |
| **Card token (HMAC, purpose, expiry)** | **REAL** | HMAC-SHA256 over `card.<payload>`, purpose inside signed material, constant-time compare, `exp` required. Forged/tampered/wrong-purpose/expired all rejected. | 15 integration tests | ✅ |
| **Card token rotation** | **REAL** | Merchant panel → `POST /customers/{id}/card-link`. Live: old link `200→400`, new `200`, membership/balance unchanged. Unauth `401`, wrong tenant `404`, forged tenant `403`. | Live + 8 tests | ✅ |
| **Wallet pass revocation** | **MISSING** | Rotation revokes the browser link and the wallet *download* URL, but an **installed pass keeps working** — it authenticates with `wallet_auth_token`, which has no rotation path. Proven: after rotation, `ApplePass <wallet_auth_token>` → `302`; wrong token → `401`. | Live | ❌ Known residual risk |
| **Gift-card secrecy** | **ACCEPTED RISK** | `code` + `remaining_value` are served to any bearer of the card URL. Confirmed live: `{"code":"AUDITGC…","remaining_value":50}`. Deliberate product decision (rendered in styled blocks for counter use). | Live | ⚠️ Accepted, documented |
| **Gift-card tenant scoping** | **REAL (hardened this audit)** | `gift_cards`, `reward_redemptions`, `customer_memberships` reads on the public card now filter `business_id`, not customer alone. | Source + db:verify | ✅ |
| **Rate limiting (enforcement)** | **REAL** | Postgres-backed (`passimo_rate_limit`), shared across instances — correct for Railway. Join limit fires at 10/min. | Live | ✅ |
| **Rate limiting (IP spoofing)** | **REAL (fixed this audit)** | Was bypassable: 13 requests → `404×10, 429×3`, then 5 with rotating `X-Forwarded-For` → **all admitted**. Now reads the trusted hop; production shape re-tested → limit holds, distinct real IP still allowed. | Live before/after + 7 unit tests | ⚠️ Requires `TRUSTED_PROXY_HOPS` set correctly |
| **Rate limiting (failure mode)** | **FAIL-OPEN** | On a database error `checkRateLimit` returns `allowed: true` for every bucket, including sign-in. | Source | ⚠️ P2 — accepted or fix |
| **Stripe webhooks** | **REAL** | Signature verified via `verifyWebhook` with 300s tolerance; replay neutralised by a unique index on `(provider, provider_event_id)` claimed before handling. | Source | ⚠️ UNVERIFIED — no forged/replayed webhook executed |
| **AI security** | **REAL** | One endpoint, six gates, forced tool-call + Zod validation, `<untrusted_data>` tags plus a system prompt that defines them, tenant filter on every customer-scoped read, metering after success. No credential → `503 not_configured`, verified live. | Prior audit + live | ✅ (architecture) / ❌ never exercised against the provider |
| **Upload safety** | **REAL** | PNG/JPEG/WebP only, decided by **magic number** not by the client's `Content-Type`; SVG explicitly excluded; size capped. | Source | ✅ |
| **XSS** | **REAL** | React escaping; three `dangerouslySetInnerHTML` uses are structured-data JSON, chart CSS vars, and legal prose — none interpolate customer input. Email renderer escapes every value. CSP `object-src 'none'`, `base-uri 'self'`. | Source | ✅ |
| **Security headers** | **REAL** | HSTS (https only), `nosniff`, `Referrer-Policy`, `Permissions-Policy`, CSP with `connect-src 'self'` and `frame-ancestors 'none'`. | Live headers | ⚠️ CSP keeps `unsafe-inline`/`unsafe-eval` |
| **Cache isolation** | **REAL (fixed this audit)** | Public card returned **no** `Cache-Control` while serving gift-card codes. Now `no-store` on every API response; QR still `public, max-age=86400`. | Live before/after | ✅ |
| **Secrets hygiene** | **REAL** | No live keys in source; `.env` gitignored and untracked; only three `NEXT_PUBLIC_*` vars, all legitimately public. | Repo scan | ✅ |
| **Audit logging** | **REAL** | `audit_log`, tenant-scoped. Rotation writes `customer.card_link_rotated`; a scan for token/URL patterns in those rows returned **0**. | Live query | ⚠️ Coverage is partial (see report) |
| **GDPR deletion** | **PARTIAL** | `passimo_anonymize_customer` sets `status='anonymized'`, rewrites email, clears notes/messages/survey text; ledger preserved (immutable by trigger). Card access dies with the status check. | Live (used for cleanup) | ✅ for erasure; no export-on-request path verified |
| **Messaging meter** | **MISSING (economic)** | `messages_per_month` is one undifferentiated meter: Pro = 50,000. No `sms`/`whatsapp` keys exist in `lib/billing/plans.ts`, yet both channels are implemented and provider-gated. | Source | ❌ Gating item |
| **Legal/public claims** | **REAL** | No GDPR-compliant / ISO / SOC 2 / encryption claims anywhere. Legal copy states plainly it is a description of behaviour, not legal advice. Privacy policy is asserted against implementation by test. | Repo scan + existing tests | ✅ |
